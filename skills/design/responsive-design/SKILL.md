# Responsive Design

Responsive design is behavior, not a list of screen sizes.

## Process
1. Identify content constraints and important actions.
2. Define fluid rules before fixed breakpoints where practical.
3. Decide what scales, wraps, stacks, collapses, moves, or disappears at each range.
4. Preserve hierarchy and interaction access as width changes.
5. Test long labels, large text, zoom, empty states, dense data, and touch.

## Avoid
Do not design only for a named device width. Do not hide essential information merely to make a screenshot look clean.

## Verification
Test representative narrow, medium, and wide viewports plus keyboard and touch interaction. Record overflow, wrapping, hit-target, focus, and hierarchy issues.
