# Layout

Start with content hierarchy and user tasks.

## Process
1. Identify primary, secondary, and supporting content.
2. Choose a composition: editorial, application shell, dashboard, catalog, split view, long-form, immersive, or another justified structure.
3. Define container behavior, grid/flex structure, spacing rhythm, alignment anchors, section rhythm, and density.
4. Define responsive transitions rather than merely shrinking desktop.
5. Define interaction zones and touch/keyboard requirements.

## Anti-patterns
- cards for every piece of information
- excessive centered hero content when the task needs information density
- arbitrary full-screen sections
- inconsistent gutters
- visual hierarchy based only on size or color
- desktop-first layouts that collapse badly on mobile

## Verification
Check at representative narrow, medium, and wide widths. Verify content order, overflow, wrapping, focus, and touch/keyboard access.
