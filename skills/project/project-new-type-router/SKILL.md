# Project New-Type Router

Do not equate every new idea with a web app.

## Route profiles

- product/application
- SaaS
- website
- web application
- mobile application
- desktop application
- CLI/tool
- API/backend service
- reusable library/package
- browser extension/integration
- client engagement
- business validation
- experiment/prototype

## Decision logic

Start from the intended outcome, users, distribution, platform, and constraints. Select the narrowest profile that fits. If the request is ambiguous, ask only questions that materially change the scaffold, architecture, repository structure, or operating model.

## Rules

A business idea may produce a validation workspace instead of software.
A client engagement may produce documentation and a private repository without code.
A desktop tool may require OS packaging and local runtime concerns that a web project does not.
A library should prioritize API stability, tests, documentation, versioning, and package publishing over UI scaffolding.
An experiment should optimize for learning and explicit expiry criteria rather than production architecture.
