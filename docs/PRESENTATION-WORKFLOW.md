# Presentation Workflow

Agent OS treats presentations as communication products with a separate narrative and slide-design grammar.

## Standard flow

DISCOVER → INTAKE → RESEARCH → NARRATIVE → VISUAL SYSTEM → SLIDE DESIGN → ASSETS → PRODUCTION → QA → ACCESSIBILITY → PRESENT

## Mode selection

- **Live talk:** optimize for rapid comprehension and speaker support.
- **Self-read/forwarded deck:** carry more explanatory context on slides.
- **Pitch deck:** emphasize problem, proof, business model, traction/evidence, differentiation, economics where appropriate, and explicit ask/next step.
- **Teaching/training:** optimize sequencing, worked examples, recall, and practice.
- **Executive/reporting:** prioritize decisions, trends, exceptions, risks, and actions.
- **Product/demo:** prioritize real product evidence, workflow clarity, and relevant screenshots.

## Visual references
Use the presentation reference catalog to discover slide structures, typography, image treatment, charts, and motion. Treat external work as inspiration/evidence unless reuse rights are established.

## Production
Prefer source-first structured content. Use PPTX when editability is required, PDF when distribution fidelity matters, and HTML when web-native interaction or animation is valuable. Verify the actual installed tooling and current documentation before depending on a version-specific API.

## QA
Every slide should have a reason to exist. Run slide-level and deck-level checks, plus target-format accessibility and rendering checks.

## Variants
For uncertain visual direction, make 2-4 distinct variants in an isolated branch/worktree, render previews, compare, record the selected direction, and promote only the winner.
