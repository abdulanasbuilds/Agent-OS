# Writing for Agents

Treat agent-facing documentation as executable guidance.

Every skill should define a narrow purpose, trigger, scope, non-scope, procedure, artifacts, permissions, and verification when relevant. Prefer progressive disclosure: keep the main skill small and move long reference material into linked files.

Before adding a skill, search for overlap. Update the manifest and routing map in the same change. Do not duplicate existing project context. Never encode unstable external API behavior as timeless fact when live official documentation can be retrieved.
