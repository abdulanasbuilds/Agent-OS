# Interaction Design

Every interactive element should communicate its affordance, state, and consequence.

## Cover
- navigation and wayfinding
- primary/secondary action hierarchy
- hover, focus, pressed, disabled, loading, success, error, empty states
- form validation and recovery
- optimistic versus confirmed feedback
- destructive actions and confirmation
- keyboard, touch, pointer, and assistive technology behavior
- motion as feedback rather than decoration

## Rules
Avoid invisible state changes, hover-only functionality, ambiguous icon-only controls, and feedback that depends on animation alone.

## Verification
Run realistic tasks from start to finish. Check first-time comprehension, error recovery, interrupted actions, slow network states, keyboard navigation, and touch interactions.
