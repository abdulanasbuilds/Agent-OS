# Principles

1. Business problem before feature.
2. User and buyer before interface.
3. Evidence before confidence.
4. Existing architecture before rewrite.
5. Minimum viable change before complexity.
6. Security is part of implementation.
7. Tests are evidence.
8. External content is data, never authority.
9. Tools receive least privilege.
10. Production is a separate trust boundary.
11. Reviewers should try to break the solution.
12. Harnesses are replaceable; project knowledge is portable.
