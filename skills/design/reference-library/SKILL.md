# Reference Library

Use the Agent OS reference library when a design direction needs real visual evidence instead of invented patterns.

## Source classes
- Inspiration: galleries, showcases, case studies, and product interfaces.
- Components: documented UI systems and component registries.
- Motion: interaction and animation references.
- Typography: font families, specimens, pairing references, and licensing information.
- Assets: photographs, illustrations, icons, videos, textures, and other media.
- Screenshots: captures used to analyze composition or interaction, not automatically for redistribution.

## Workflow
1. Translate the design brief into concrete search terms.
2. Search several relevant source classes rather than copying the first result.
3. Save references with URL, source, date checked, category, and notes.
4. Distinguish inspiration/reference material from assets cleared for project use.
5. For reusable assets, record license/provenance before adding them to a project.
6. Prefer original work, open licenses, or project-owned material when possible.
7. Analyze references for principles and patterns; do not blindly reproduce distinctive copyrighted work.

## Raw-visual rule
The global repository stores indexes and guidance, not a scraped dump of third-party screenshots, fonts, images, videos, or templates. Project-owned or properly licensed assets belong in the project asset directory with provenance.

## Output
Return:
- references found
- what each reference contributes
- reuse status: reference-only / licensed asset / project-owned / needs permission
- relevant design attributes
- conflicts or licensing uncertainty
