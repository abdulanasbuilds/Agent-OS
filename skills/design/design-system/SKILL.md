# Design System

A design system is the smallest reusable vocabulary that keeps the product coherent without flattening its personality.

## Process
1. Extract the approved visual direction.
2. Define semantic tokens rather than scattering raw values.
3. Establish typography roles and scale.
4. Establish color roles for surfaces, content, actions, feedback, and data.
5. Establish spacing, radii, borders, shadows/elevation, and interaction states.
6. Define component anatomy and allowed variants.
7. Define responsive and accessibility rules.
8. Document exceptions deliberately rather than creating one-off overrides.

## Anti-slop rule
Do not force every page into the same card/grid pattern. The system should support the product's information architecture.

## Verification
Check theme consistency, contrast, focus states, dense and sparse screens, mobile widths, and state coverage. Keep the token set small enough to understand and maintain.
